# Tempo — шахматные часы

Веб-приложение на русском языке для игры за одной доской. Интерфейс в стиле Apple, две большие области нажатия и удобное управление с телефона.

## Возможности

- Режимы 1+0, 3+2, 5+3, 10+0, 15+10 и собственное время с добавлением за ход.
- Пауза, смена цветов, подтверждение сброса, победа по времени и результат вручную.
- Регистрация и вход по email и паролю.
- Профили игроков, победы, поражения, ничьи, личный счёт и история партий.
- Разворот верхних часов на телефоне, режим фокуса, звук и виброотклик.
- Пробел переключает ход, Esc ставит часы на паузу.

Письма для подтверждения адреса и восстановления пароля пока не подключены.

## Бесплатное размещение

Пошаговая инструкция: **[DEPLOY.md](DEPLOY.md)**.

## Локальный запуск

Нужны Node.js 24 и pnpm. В package.json закреплена версия менеджера пакетов.

```sh
corepack enable
pnpm install --frozen-lockfile
cp .env.example .env.local
pnpm db:migrate
pnpm dev
```

Откройте http://localhost:3000. По умолчанию данные хранятся в локальном SQLite-файле tempo.local.db. В Vercel используются удалённая база и секретный токен Turso.

## Проверка

```sh
pnpm test
pnpm typecheck
pnpm build
pnpm test:api
```

API-проверка запускает собранное приложение с отдельной временной базой и удаляет её после завершения. Она проверяет регистрацию, вход, выход, принадлежность данных, победы и ничьи, повторную отправку результата, неверный пароль и защиту от запросов с другого сайта. Рабочая база не используется.

## Устройство приложения

Next.js, React, TypeScript, Tailwind CSS, libSQL/Turso. Интерфейс — app/chess-app.tsx; логика часов — lib/clock.ts; серверные маршруты — app/api/; схема — db/schema.ts; миграции — drizzle/.

Часы вычисляют остаток по временным отметкам: ограничения фоновых вкладок не замораживают отсчёт. Черновик партии хранится во вкладке браузера; подтверждённые результаты — в базе. Уникальный идентификатор партии предотвращает повторное начисление очков.

Пароли хешируются scrypt с индивидуальной солью. Токены сессий хранятся в базе в виде хеша; cookie — HttpOnly, SameSite и Secure на HTTPS. Владение данными проверяется на сервере. Изменения требуют проверки Origin и отдельного заголовка; попытки входа ограничены. Секреты задаются только в окружении сервера.
